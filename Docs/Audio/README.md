# KICK Back audio first pass

Verified production source: `6fd32a9c873436c4e5420b673730ceae2f43c0a4`.

Nine original project-created mono WAV recordings, generated by `Tools/generate_audio.py` (Python + NumPy). No third-party recordings or samples. This is temporary synthesized sound design, not final commissioned Foley or music.

- Lobby: eight-bar A minor instrumental, 90 BPM.
- Battle: eight-bar instrumental, 120 BPM, stronger percussion.
- Effects: Hit, Whoosh, Block, Parry, Down, Menu, Success.

CombatAudioEmitter subscribes to existing strike/damage/dodge events without changing combat timing or health. DamageKind chooses actual hit, block and parry sounds; lethal damage uses Down. Dynamically created actors are also bound. Menu clicks play Menu and completed tutorial steps play Success. Lobby/battle tracks switch at Start; returning to lobby recreates the lobby audio. Sources are 2D and use independent music/effects volume settings under Master. WebGL uses KickBackAudio.jslib with copied WAV assets and a dedicated Web Audio context; editor/desktop retains AudioSource playback. The direct browser backend was separately tested for lobby, battle, effects and mute before integration. The WebGL host resumes its audio context on trusted pointer/keyboard interaction. Native browser tracks decode before scheduling and resume on interaction. Desktop/editor music waits for decoded clip data and retries deferred initial playback. Browser autoplay rules require user interaction.

Validation: all nine PCM assets checked for nonzero audio and unclipped peaks; C# syntax configurations passed. Actual Unity WebGL build and browser test passed. The browser analyser measured nonzero output after interaction in lobby and battle, silence with music at zero, and resumed sound after restoring music volume. Real menu, strike, successful hit and tutorial transitions emitted their audio events. Existing HUD checks at four resolutions and two authored-motion regression reviews also passed with no runtime errors. See audio.json for measurements. Guard/parry routes were reviewed in code; the live tutorial test stops at Guard and does not claim to have audibly exercised those two. The Down event was also observed.
